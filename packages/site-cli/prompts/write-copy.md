# 写站点文案（生成通道）

给 `sites/<slug>/content/{en,zh}/` 用。只读该站 `industry.json` 和本文件。不要把 `validate` 条文、源站对照或「不要写成某行业」写进页面。

## 简报三层，缺一层就先补简报

| 层 | 字段 | 用途 | 单独使用时的失败 |
|----|------|------|------------------|
| 对象 | `visitors` `deliverables` `catalog` `pages` `catalogPrefix` | 路由、导航、写谁、卖哪类 | 把名单拼进每句 →「共用一套」 |
| 痛点 | `pains` | 买家已经在烦的事 | 没有痛点 → 标题像口号，戳不到人 |
| 说法 | `phrases` `references` | 行业怎么报数字、要什么材料 | 没有说法 → 过度提炼，不像跟单 |

`references` 只记我们自己的笔记：URL + 他们报的数字、物件、动作、怕什么。禁止把竞品段落搬进 `content/`。

对象齐、痛点或说法空：先补 `industry.json`，不要用对象层发明句子。

## 先采证，再写

1. 打开 2--3 个同业工厂 / OEM 首页（该站品类，不是隔壁行业）。
2. 用自己的话写下：起订、打样天数、先寄什么、签字后才做什么、买家怕什么。
3. 写入 `pains`、`phrases`、`references`。
4. 再写 `content/`。

## 各区块用哪一层

- **hero**：品类 + 买家第一步 + 行业常用数字（起订、打样日）。不要只写一句提炼过的定位。
- **audiences**：每个访客一条他自己的痛，不复述访客名单，不写「他们共用一套」。
- **capabilities**：车间真正做的事（放码、克重、绣花、水洗），不要「一份档案管全程」。
- **process**：材料怎么进来、哪一步签字、哪一步才开裁 / 装箱。
- **cta**：叫他寄什么，几天内回什么。

标题说过的信息，描述换一件事。不要把 `visitors` + `deliverables` 拼成万能句。

## 写完两问

1. **扫一眼**：买家知不知道该寄什么、能得到什么（起订 / 样品 / 下一步）？
2. **像不像行内**：跟单或采购听得懂，还是像品牌文案在概括？

两问过不了，回到简报补痛点和说法，不要再把句子改得更短。

## 三种已经失败过的生成

都发生在写 `content/`，不在 `create` / `validate`：

1. 生成指令里带「不要写成某行业」→ 对照句进标题。
2. 只拿对象层「正向拼接」→「共用一套工艺单，从样跟到货」。
3. 只下令「各区块换一件事、禁止复述」→ 过度提炼，没有行业说法。

本文件是生成提示词。对象层管路由；痛点和说法管句子。`validate` 只拦空字段、源站全等、对照式否定和死链，不定义好文案。
