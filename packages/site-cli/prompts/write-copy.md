# 写站点文案（生成通道）

给 `sites/<slug>/content/{en,zh}/` 用。只读该站 `industry.json` 和本文件。不要把 `validate` 条文、源站对照或「不要写成某行业」写进页面。

首页是一条**买家评估路径**，不是一个信息反复粘贴的板子。每个 Blueprint 区块只回答一个问题；痛点和说法要**分配到对的区块**，不能整块首页都写成打样须知或下单后投诉。

---

## 简报三层，缺一层就先补简报

| 层 | 字段 | 用途 | 单独使用时的失败 |
|----|------|------|------------------|
| 对象 | `visitors` `deliverables` `catalog` `pages` `catalogPrefix` | 路由、导航、写谁、卖哪类 | 把名单拼进每句 →「共用一套」 |
| 痛点 | `pains` | 买家已经在烦的事 | 没有痛点 → 标题像口号，戳不到人 |
| 说法 | `phrases` `references` | 行业怎么报数字、要什么材料 | 没有说法 → 过度提炼，不像跟单 |

`references` 只记我们自己的笔记：URL + 他们报的数字、物件、动作、怕什么。禁止把竞品段落搬进 `content/`。

对象齐、痛点或说法空：先补 `industry.json`，不要用对象层发明句子。

---

## 痛点进哪个区块

`pains` 不是每段标题都要写一遍。先判断这是哪类痛，再放进对应区块：

| 痛点类型 | 例子 | 应出现的区块 |
|----------|------|--------------|
| 选型 / 立项 | 起订太高测不了款；没有工艺单开不了工 | **audiences**（这类买家要什么）、**capabilities**（你能怎么接） |
| 能力 / 规格 | 克重洗后不对；床笠高度套不上 | **capabilities**、**metrics** |
| 启动 / 流程 | 不知道先寄什么；不知道哪步签字 | **process**、**cta** |
| 交付 / 售后 | 大货对不上签字样；补货色差 | **warranty-cases**、内页 |
| 信任 / 合规 | 要 OEKO-TEX 跟批次；要 AQL 报告 | **assurances**、**warranty-cases** |

**禁止**：把「第一单投诉」「收过定金后的纠纷」写进 **audiences** 或 **hero**。那是 **warranty-cases** 和内页的事。

---

## 首页区块职责（Blueprint → `home.json`）

顺序见各站 `blueprints/home.json`。写每块前先问：**买家在这一屏要判断什么？**

| 区块 ID | 买家在判断什么 | 文案职责 | 语气 / 长度 | 不要写成 |
|---------|----------------|----------|-------------|----------|
| `hero-fullbleed` | 我来对地方了吗？ | **定位**：做什么品类、服务谁、一个可验证的差异点 | 一句主标题 + 一段范围说明；可带一个数字，但不是完整 RFQ | 打样须知、流程步骤、投诉清单、「发 XX 几天回 YY」占满首屏 |
| `assurance-bar` | 有没有明显红旗？ | **信任芯片**：认证、质检方式、响应时效 | 4 条，每条 title + 一行 proof | 重复 hero 数字；写成长段落 |
| `metrics-bar` | 规模和能力是否真实？ | **量化背书**：MOQ、周期、规格区间、覆盖范围 | 数字 + 短 label | 形容词；痛点句 |
| `audience-cards` | 有没有适合我的入口？ | **按角色分流**：每类访客在本项目里要达成什么、选供应商时看什么 | 正面：目标 + 选型标准；链到该角色内页 | 下单后投诉；「共用一套」；四类复制同一结构 |
| `capabilities-grid` | 能不能做我要的东西？ | **能力证明**：交付物 + 买家用来筛厂的规格维度 | 车间 / 产线 / 交付物 + 可核对参数 | 「一份档案管全程」；空泛「全工艺」 |
| `process-timeline` | 怎么启动？风险在哪？ | **路径透明**：材料进 → 哪步批准 → 哪步才量产 | 5 步左右，每步写输入或签字点 | 品牌口号；与 **cta** 逐步重复 |
| `rooms-grid` | 有哪些品类可看？ | **品类导航**：label + slug | 几乎只要品类名 | 销售文案 |
| `testimonials` | 同行信不信？ | **社会证明**：结果 + 角色 / 地区 | 一句 outcome，不堆术语 | 无出处形容词；把 process 再讲一遍 |
| `warranty-cases` | 出事怎么办？ | **风险反转**：交付后可能出的问题 + 书面承诺 | 问答式，具体补救 | 放到 audiences；空泛「质量保证」 |
| `contact-cta` | 我现在该寄什么、几天有回音？ | **转化**：附件字段、回复时效、3 步下一步 | 行动导向；可写 MOQ / 打样日 | 重复 hero 定位；讲公司历史 |
| `projects-showcase` | 做过类似项目吗？ | **案例**：地区、数量、周期、解决了什么 | 有数字的结果 | 只有形容词 |
| `ecosystem` | 背后产研资源如何？ | **产研 / 区位背书**（若启用） | 能力 + 地理分工 | 与 capabilities 完全重复 |

**区块间分工**：标题说过定位，描述换**另一件事**（范围、证据、路径、行动）。不要把 `visitors` + `deliverables` 拼成万能句，也不要把 **cta** 的信息提前塞进 **hero**。

## 不同行业：各区块该传递什么

对象层决定「写谁、卖哪类」；下面是要在本行业**说进对应区块**的信息，不是句模。

### 成衣 OEM / ODM（`textile-apparel`）

| 区块 | 应传递的信息 |
|------|----------------|
| hero | 针织 / 梭织车缝；服务品牌 / 零售 / 代理；OEM·ODM、放码、大货出口 |
| assurances | BSCI、AQL、PP 前不开裁、48h 报价 |
| metrics | 起订（款 / 色）、首样天数、码段、PP 节点 |
| audiences | 品牌：返单版型一致；零售：低起订测款；代理：交期可写进邮件；开发：无工艺单可用参考样开报价 |
| capabilities | 工艺单、放码、初样 / 试穿 / PP、针织线 / 梭织线、出口装箱 |
| process | 工艺单或参考样 → 报价 → 试穿 → 签 PP → 大货 |
| warranty | 大货尺寸漂移、缩水、少箱 → 对照签字样 / AQL 的处理 |
| cta | 附工艺单或成衣照；48h 内 MOQ + 打样日 |

### 家纺 / 酒店床品（`textile-home`）

| 区块 | 应传递的信息 |
|------|----------------|
| hero | 酒店床品、卫浴毛圈、窗帘；服务酒店 / 零售 / 地产；套装与绣花可定制 |
| assurances | OEKO-TEX 跟批次、套装样铺床、水洗后锁克重 |
| metrics | 套装样周期、GSM 区间、床笠垂边 / 床垫高度、绣花确认样 |
| audiences | 酒店：洗后手感与耐用；零售：补货白度一致；地产：按房型清单打包；开发：Logo 大货前确认 |
| capabilities | 床单 / 支数、毛圈、绣花、按套装装箱 |
| process | 房型清单 → 锁规格 → 套装样 → 签字 → 大货 |
| warranty | 批次证书、绣花偏差、套装不齐 |
| cta | 房型清单、床垫高度、克重目标或绣花稿 |

### 面料 sourcing（`textile-fabric`）

| 区块 | 应传递的信息 |
|------|----------------|
| hero | 梭织 / 针织面料；服务品牌 / 工厂 / 贸易商；规格先行 |
| audiences | 品牌：季节系列稳定；工厂：大货规格锁定；贸易商：出口单证 |
| capabilities | 成分 / 克重、打色 / lab dip、MOQ / 交期、出口卷装 |
| process | 规格 → 配厂 → lab dip 签字 → 大货 → 出货 |
| cta | 成分、克重、门幅、颜色、数量 |

### 家具 / 整案（`ratahome-furniture`）

| 区块 | 应传递的信息 |
|------|----------------|
| hero | 整案伙伴：设计、定制、交付；服务海外住宅 / 项目 |
| audiences | 业主 / 设计师 / 开发商 / 酒店各自项目目标 |
| capabilities | 家具、定制柜、灯光软装、项目交付 |
| process | 需求 → 方案 → 选品 → 生产 → 验货出货 |
| warranty | 运输破损、结构质保、缺件响应 |

新行业：先填 `industry.json` 对象层，再按上表**逐区块**列出「这一行该出现什么信息」，然后写句子。

## 先采证，再写

1. 打开 2--3 个同业工厂 / OEM 首页（该站品类，不是隔壁行业）。
2. 按区块记笔记：他们 hero 定位什么、capabilities 报哪些参数、process 几步、cta 要什么材料。
3. 用自己的话写入 `pains`、`phrases`、`references`。
4. 再写 `content/`。

---

## 写完怎么验收（按路径，不是按句式）

1. **三秒定位**（hero）：陌生买家能否说出「做什么、给谁」？
2. **角色分流**（audiences）：每类访客是否看到**自己的项目目标**，而不是投诉或同一句话？
3. **能力筛选**（capabilities + metrics）：工程师 / 采购能否用页面上的参数判断「能不能做」？
4. **启动清晰**（process + cta）：是否知道先寄什么、哪步签字、几天有回复？
5. **风险有底**（warranty + assurances）：交付后问题是否在 warranty 有书面说法？

五问里有一两问不过，回到**对应区块**和简报补信息；不要把所有区块都改成更短的口号，也不要把 **cta** 的内容提前塞进 **hero**。

## 三种已经失败过的生成

都发生在写 `content/`，不在 `create` / `validate`：

1. 生成指令里带「不要写成某行业」→ 对照句进标题。
2. 只拿对象层「正向拼接」→「共用一套工艺单，从样跟到货」。
3. 只下令「各区块换一件事、禁止复述」→ 过度提炼，没有行业说法。
4. **把跟单术语和打样须知铺满每个区块** → hero 像 RFQ，audiences 像投诉区，capabilities 像车间日报；买家还没建立信任就被要求「发工艺单」。

本文件是生成提示词。对象层管路由；痛点和说法管**该进哪个区块的句子**。`validate` 只拦空字段、源站全等、对照式否定和死链，不定义好文案。
